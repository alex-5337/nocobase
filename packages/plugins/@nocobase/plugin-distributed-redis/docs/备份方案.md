# 主备人工切换部署运维方案（极简版）

<br />

***

## 1. 方案概述

两台服务器，一主一备：

- **平时**：只有主服务器运行 NocoBase，备机只有 PostgreSQL 在跑（同步数据）
- **主挂了**：管理员手动 promote 备库、在备机启动 NocoBase，改域名指向，完成切换
- **数据保障**：PostgreSQL 流复制 + 本地文件夹实时同步（lsyncd），数据不丢
- **文件保障**：上传的文件存主服务器本地目录，lsyncd 实时同步到备机。**前提是同步正常运行**，切换前需人工确认备机文件完整
- **切换时间**：取决于管理员响应，通常 5\~30 分钟

***

## 2. 总体架构

```
平时：
  用户 → 域名 → 主服务器（NocoBase + PG 主库 + 本地文件存储）
                     │              │
                     │ 异步流复制    │ lsyncd 实时同步
                     ▼              ▼
                备服务器（PG 备库 + 同步过来的文件）

主挂了：
  管理员 promote 备库为主库（备库只读，必须先 promote）
  管理员在备机启动 NocoBase
  管理员改 DNS 指向备服务器
  备机文件已同步，立即可用
```

***

## 3. 部署前准备

| 项          | 要求                     | 说明                                |
| ---------- | ---------------------- | --------------------------------- |
| 服务器        | 2 台，配置相同               | 一主一备                              |
| OS         | Linux（Ubuntu/CentOS）   | -                                 |
| NocoBase   | 两台相同版本                 | 代码和插件版本一致                         |
| PostgreSQL | 两台相同大版本                | 如 16.x                            |
| 文件同步       | lsyncd 或 rsync+inotify | 主 → 备单向实时同步                       |
| 存储目录       | 两台相同路径                 | 如 `/opt/nocobase/storage/uploads` |
| 域名         | 一个域名，能改 DNS            | 切换时改指向                            |

**文件同步必须提前配好并验证**：上传一个文件，检查备机是否同步。配置方法见 5.3 节。

***

## 4. 数据库配置（PostgreSQL 流复制）

### 4.1 主库配置（在主服务器上执行）

```bash
# 1. 编辑 PostgreSQL 配置文件
sudo nano /etc/postgresql/16/main/postgresql.conf
```

修改以下配置：

```ini
wal_level = replica
max_wal_senders = 4
max_replication_slots = 4
```

```bash
# 2. 允许备库连接
sudo nano /etc/postgresql/16/main/pg_hba.conf
```

添加一行（把 `备服务器IP` 换成实际 IP）：

```
host  replication  replica_user  备服务器IP/32  scram-sha-256
```

```bash
# 3. 创建复制用户
sudo -u postgres createuser --replication --login replica_user
sudo -u postgres psql -c "ALTER USER replica_user WITH PASSWORD '你的密码';"

# 4. 重启 PostgreSQL
sudo systemctl restart postgresql

# 5. 验证（应该返回一行）
sudo -u postgres psql -c "SELECT * FROM pg_replication_slots;"
```

### 4.2 备库配置（在备服务器上执行）

```bash
# 1. 停止 PostgreSQL，清空数据目录
sudo systemctl stop postgresql
sudo rm -rf /var/lib/postgresql/16/main/*

# 2. 从主库拉取数据（把 主服务器IP 换成实际 IP）
sudo -u postgres pg_basebackup -h 主服务器IP -U replica_user \
  -D /var/lib/postgresql/16/main -R -X stream -C -S nb_standby_slot

# 3. 启动 PostgreSQL（自动进入备库模式）
sudo systemctl start postgresql

# 4. 验证（应该返回 't' 表示是备库）
sudo -u postgres psql -c "SELECT pg_is_in_recovery();"
```

### 4.3 日常检查复制是否健康

在主服务器上执行：

```bash
sudo -u postgres psql -c "SELECT client_addr, state, sync_state FROM pg_stat_replication;"
```

应该看到一行，`state = streaming` 表示正常。

## 5. 应用配置（NocoBase）

### 5.1 主服务器（平时运行）

正常安装 NocoBase，`.env` 配置：

```bash
DB_HOST=localhost
DB_PORT=5432
DB_DATABASE=nocobase
DB_USER=nocobase_user
DB_PASSWORD=你的密码

# 文件存储用本地（默认）
# 不需要额外配置，NocoBase 默认存储在 storage/uploads

# 实例 ID
NOCOBASE_INSTANCE_ID=0
```

启动：

```bash
yarn nocobase start
# 或
pm2 start nocobase
```

### 5.2 备服务器（平时不启动 NocoBase）

安装相同版本的 NocoBase 代码，`.env` 配置：

```bash
DB_HOST=localhost
DB_PORT=5432
DB_DATABASE=nocobase
DB_USER=nocobase_user
DB_PASSWORD=你的密码

# 相同配置，实例 ID 不同
NOCOBASE_INSTANCE_ID=1
```

**不要启动 NocoBase**，只有 PostgreSQL 在跑。

**关键**：两台 NocoBase 的存储路径必须相同（默认 `storage/uploads`），lsyncd 同步这个目录。下文以 `/opt/nocobase/storage/uploads` 为例，请按实际部署路径替换。

### 5.3 文件同步配置（lsyncd）

**在主服务器上安装配置 lsyncd**：

```bash
# 安装
sudo apt install lsyncd

# 配置 /etc/lsyncd/lsyncd.conf.lua
```

```lua
settings {
    logfile = "/var/log/lsyncd/lsyncd.log",
    statusFile = "/var/log/lsyncd/lsyncd.status",
    inotifyMode = "CloseWrite",
    maxProcesses = 1
}

sync {
    default.rsync,
    source = "/opt/nocobase/storage/uploads",
    target = "备服务器IP:/opt/nocobase/storage/uploads",
    rsync = {
        archive = true,
        compress = true,
        verbose = true
    },
    ssh = {
        port = 22
    }
}
```

```bash
# 启动
sudo systemctl enable --now lsyncd

# 验证
sudo systemctl status lsyncd
tail -f /var/log/lsyncd/lsyncd.log
```

**SSH 免密登录**（主 → 备）：

```bash
# 在主服务器上生成密钥
ssh-keygen -t rsa

# 复制到备服务器
ssh-copy-id 备服务器IP

# 测试
ssh 备服务器IP "echo OK"
```

**验证同步**：

```bash
# 在主服务器上创建测试文件
echo "test" > /opt/nocobase/storage/uploads/test.txt

# 等 1~2 秒，在备服务器上检查
cat /opt/nocobase/storage/uploads/test.txt
# 应该输出 test

# 验证完成后删除测试文件（两边都会同步删除）
rm /opt/nocobase/storage/uploads/test.txt
```

**注意事项**：

1. lsyncd 是**单向同步**（主 → 备），切换后如果要在新主上继续同步，需要在新主上重新配置
2. 同步延迟通常 1\~2 秒，大文件可能更长
3. 如果同步中断，切换前需要人工确认备机文件完整
4. 替代方案：rsync 定时任务（每 5 分钟），但实时性不如 lsyncd

## 6. 切换操作（Runbook）

### 6.1 主服务器宕机（完整流程）

#### 步骤 1：确认主服务器宕机

```bash
ping 主服务器IP
# 不通

curl http://主服务器IP:13000
# 无法连接
```

或登录云控制台查看服务器状态，确认已停机。

#### 步骤 2：检查备机文件完整性

```bash
ls -la /opt/nocobase/storage/uploads/
```

对比主服务器最后的文件列表，确认 lsyncd 同步正常。

> ⚠️ 如果同步中断且主服务器还能连上，紧急补救：
>
> ```bash
> rsync -avz 主服务器IP:/opt/nocobase/storage/uploads/ \
>   /opt/nocobase/storage/uploads/
> ```

#### 步骤 3：promote 备库为主库（关键！）

备库平时是只读的（streaming replication standby），NocoBase 启动时需要写数据库（建表、迁移、会话等），直接启动会失败。必须先把备库 promote 为可读写的主库：

```bash
sudo -u postgres pg_ctl promote -D /var/lib/postgresql/16/main
```

验证 promote 成功：

```bash
sudo -u postgres psql -c "SELECT pg_is_in_recovery();"
```

应该返回 `f`（false），表示已脱离备库模式，成为可读写的主库。

#### 步骤 4：启动 NocoBase

```bash
cd /path/to/nocobase
yarn nocobase start
# 或
pm2 start nocobase
```

等待 1\~2 分钟，验证能访问：

```bash
curl http://localhost:13000/__health_check
```

#### 步骤 5：修改 DNS 指向备服务器

登录域名管理后台（阿里云/腾讯云/Cloudflare），把 A 记录从主服务器 IP 改成备服务器 IP。

> 💡 建议 TTL 设短一点（如 60 秒），加快 DNS 生效。

#### 步骤 6：验证切换完成

- 访问域名，能打开网站
- 登录后台，能正常读写数据
- 检查文件，能正常下载（备机文件已同步）

**切换时间**：步骤 3\~4 约 2\~3 分钟 + DNS 生效时间（通常 1\~10 分钟，取决于 TTL）。

### 6.2 主库进程挂了，但服务器还活着

```
步骤 1：在主服务器上重启 PostgreSQL
  ssh 管理员@主服务器IP
  sudo systemctl restart postgresql

步骤 2：如果重启失败，按 6.1 流程切换到备机
```

### 6.3 主服务器恢复后，重新加入为备

> ⚠️ 原主服务器恢复后**不能直接启动投入使用**：主宕机期间原备机已 promote 为新主，两边数据库时间线已分叉，原主上的旧数据可能与新主不一致。必须清空原主的数据目录，从新主重新 clone。

#### 步骤 1：确认原主上没有运行 NocoBase

原主恢复开机后，如果 NocoBase 配了开机自启（pm2/systemd），可能已自动启动。它的数据库马上要被清空重建，先确认 NocoBase 处于停止状态：

```bash
pm2 list
# 如果在运行，停止并取消自启
pm2 stop nocobase
pm2 disable nocobase 2>/dev/null || true
```

#### 步骤 2：在新主（原备机）上放行新备的复制连接

编辑新主的 `pg_hba.conf`：

```bash
sudo nano /etc/postgresql/16/main/pg_hba.conf
```

把原来允许备服务器的那行 IP 改为原主服务器 IP（新备）：

```
host  replication  replica_user  原主服务器IP/32  scram-sha-256
```

重新加载配置：

```bash
sudo systemctl reload postgresql
```

#### 步骤 3：在原主（新备）上重新 clone 数据

清空旧数据目录，从新主全量拉取：

```bash
sudo systemctl stop postgresql
sudo rm -rf /var/lib/postgresql/16/main/*

sudo -u postgres pg_basebackup -h 新主IP -U replica_user \
  -D /var/lib/postgresql/16/main -R -X stream -C -S nb_standby_slot

sudo systemctl start postgresql
```

验证已进入备库模式（应该返回 `t`）：

```bash
sudo -u postgres psql -c "SELECT pg_is_in_recovery();"
```

在新主上验证复制链路（应该看到新备在 `streaming`）：

```bash
sudo -u postgres psql -c "SELECT client_addr, state FROM pg_stat_replication;"
```

#### 步骤 4：反转文件同步方向（保持 主 → 备 单向）

新主（原备机）现在是数据源，同步方向必须反过来。

在新备（原主服务器）上停止并禁用 lsyncd：

```bash
sudo systemctl disable --now lsyncd
```

在新主（原备机）上配置 lsyncd，source 指向本机目录，target 指向新备，并配置新主 → 新备的 SSH 免密登录（配置方法同 5.3 节）。

> 💡 首次同步建议先在新主上手动全量执行一次，避免遗漏切换期间的文件：
>
> ```bash
> rsync -avz /opt/nocobase/storage/uploads/ 新备IP:/opt/nocobase/storage/uploads/
> ```

#### 步骤 5：验证文件同步方向正确

在新主上创建测试文件：

```bash
echo "test" > /opt/nocobase/storage/uploads/test.txt
```

在新备上确认能收到：

```bash
cat /opt/nocobase/storage/uploads/test.txt
```

验证完成后删除测试文件（两边都会同步删除）。

#### 步骤 6：DNS 切回（可选，不建议）

建议保持现状，让原备机继续当主，避免再次切换的风险。

如果确实要让原主服务器重新当主，需完整再走一遍切换流程：按 6.1 流程把原主（当前是备）promote 并启动 NocoBase、改 DNS 指回原主，然后按本节流程把原备机重新加入为备。

## 7. 监控告警（简化）

只需要监控主服务器是否活着，以及两条同步链路是否正常：

| 监控项    | 工具                            | 告警方式           |
| ------ | ----------------------------- | -------------- |
| 主服务器存活 | 云监控 / 第三方拨测（如 UptimeRobot）    | 短信/邮件/钉钉       |
| 主库进程   | `systemctl status postgresql` | 异常时告警          |
| 复制状态   | `pg_stat_replication` 查询      | 备库断开时告警        |
| 文件同步状态 | `systemctl status lsyncd` 或日志 | lsyncd 异常或同步中断 |
| 同步延迟   | 对比两台文件修改时间                    | 延迟超过 1 分钟告警    |

**推荐**：用云厂商的监控（阿里云云监控、腾讯云可观测平台）或 UptimeRobot 免费拨测，主服务器不通立即短信通知管理员。

## 8. 升级流程

先在备机上完成升级并验证，再切流量，最后把旧主重新加入为备。

### 步骤 0：确认文件同步正常

在主服务器上 touch 一个测试文件，检查备机是否同步：

```bash
touch /opt/nocobase/storage/uploads/.sync-test
```

在备机上确认存在后，删除测试文件。

### 步骤 1：在备服务器上升级 NocoBase 代码

```bash
cd /path/to/nocobase
git pull  # 或上传新代码
yarn install
```

### 步骤 2：promote 备库为主库（关键！）

备库是只读的，`yarn nocobase upgrade` 需要写数据库，必须先 promote：

```bash
sudo -u postgres pg_ctl promote -D /var/lib/postgresql/16/main
```

验证（应该返回 `f`）：

```bash
sudo -u postgres psql -c "SELECT pg_is_in_recovery();"
```

### 步骤 3：在备服务器上执行数据库升级

```bash
yarn nocobase upgrade
```

### 步骤 4：启动备机 NocoBase，验证功能

```bash
yarn nocobase start
# 或
pm2 start nocobase
```

确认新版本功能正常。

### 步骤 5：DNS 切到备机

把 A 记录改为备服务器 IP，用户访问新系统。

### 步骤 6：旧主服务器重新加入为备

按 6.3 流程操作。

## 9. 方案对比

| <br /> | 方案乙（完整版）                                | 方案乙（极简版，本方案）               |
| ------ | --------------------------------------- | -------------------------- |
| 机器数    | 2 台                                     | 2 台                        |
| 自动化程度  | 高（VIP 漂移 + 手动 promote）                  | **低（全人工）**                 |
| 额外组件   | Nginx + Keepalived + PgBouncer + repmgr | **无（仅 lsyncd）**            |
| 切换时间   | 管理员响应 + 1 分钟                            | 管理员响应 + DNS 生效时间（5\~30 分钟） |
| 数据安全   | 秒级 RPO                                  | 秒级 RPO                     |
| 文件存储   | 云对象存储                                   | **本地文件夹 + lsyncd 同步**      |
| 文件安全   | 云厂商保障                                   | **依赖同步正常运行**               |
| 运维复杂度  | 中                                       | **低**                      |
| 适合     | 有一定运维能力                                 | **运维能力有限，接受人工切换**          |
